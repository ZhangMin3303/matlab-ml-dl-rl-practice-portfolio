## 修复内容

### 1. 路径修复

原问题：

- `code/shuzishibie99.m` 曾使用类似 `[local desktop path]\data0.mat` 的本机桌面绝对路径。
- 这种写法换电脑、换文件夹后无法运行。

修复方式：

- 改为基于脚本位置的相对路径。
- 主脚本 `shuzishibie9.m` 从同级 `data/` 读取数据。
- 子文件夹脚本 `code/shuzishibie99.m` 从上一级 `data/` 读取数据。

影响：

- 不改变算法逻辑。
- 提升可复现性和可移植性。

### 2. 数据整理

原问题：

- 原始本地数据曾主要保存在 `data_shuzishibie.zip` 中；公开版不上传该压缩包。
- 代码运行时需要直接读取 `.mat` 文件。

修复方式：

- 将 zip 中的 12 个 `.mat` 文件解压到 `data/` 文件夹。
- 使用 MATLAB `whos('-file', ...)` 验证每个 `.mat` 文件可读。

影响：

- 不改变数据内容。
- 让脚本可以直接运行。

### 3. 批处理运行适配

原问题：

- 原代码使用 `training-progress` 图形训练窗口。
- 自动验证和命令行批处理运行时，图形窗口不适合长期归档验证。

修复方式：

- 将训练选项改为：

```matlab
'Verbose', false, ...
'Plots', 'none'
```

影响：

- 不改变模型结构。
- 不改变训练目标。
- 只改变运行时显示方式。

### 4. 准确率计算修复

原问题：

- 原代码使用：

```matlab
accuracy = 1 - sum(predictedLabels == testLabels) / numel(testLabels);
```

- 这个公式计算的是错误率方向，不是准确率。
- 同时，测试标签原本是行向量，`predictedLabels` 是列向量，二者比较会产生矩阵，导致输出一串数字而不是单个准确率。

修复方式：

- 将测试标签改为列向量。
- 将准确率公式改为：

```matlab
accuracy = sum(predictedLabels == testLabels) / numel(testLabels);
```

影响：

- 修复评价指标含义。
- 让输出结果成为单个准确率数值。

当前验证输出：

```text
Accuracy: 83.3333%
```

### 5. 随机种子固定

修复方式：

```matlab
rng(1);
```

影响：

- 固定随机初始化和训练过程中的随机性。
- 便于重复运行得到稳定结果。
